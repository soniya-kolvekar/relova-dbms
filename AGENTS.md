# Relova DBMS — AI Agent Operating Guidelines

This document provides architectural standards, constraints, and instructions for any AI developer agents collaborating on **Relova DBMS**.

---

## 1. Project Mission & Identity
Relova is an industrial surplus material exchange platform. This repository (`relova-dbms`) is the **Simplified Academic DBMS Edition**, tailored to showcase relational schema design, transactional integrity, stored procedures/triggers, and clean full-stack integration with Supabase PostgreSQL.

---

## 2. Core Architectural Invariants

### 1. Exactly 8 PostgreSQL Tables
Under no circumstances should new tables be introduced without direct user authorization. The schema is strictly confined to:
1. `users`: Unified dual operator nodes (`role: 'both'`).
2. `material_categories`: Static/standard material taxonomy with emission factors.
3. `resource_lots`: Surplus lots published by industrial nodes.
4. `demand_requests`: Recipient material demands.
5. `matches`: Bilateral compatibility pairings (auto-generated by trigger).
6. `exchanges`: Active custody agreements and physical scale weigh-ins.
7. `exchange_events`: Immutable audit trail of lifecycle status transitions.
8. `impact_records`: Calculated ESG metrics (landfill diverted kg, CO₂e saved, water conserved).

### 2. Zero Mock / Static Data Policy
- Do not use hardcoded arrays of fake numbers or fake transactions.
- All numbers, lists, cards, and charts must be derived from or written directly to the 8 Supabase PostgreSQL tables.
- When tables are empty, render clean industrial zero-state cards with actionable prompts.

### 3. Image Free Policy
- Do not implement image upload forms, S3 storage buckets, or external image links.
- Use clean, non-AI Lucide industrial category icons (`Boxes`, `Package`, `Layers`, `Hammer`, `Scissors`, `ShieldCheck`).

### 4. Unified Dual Dashboard
- Do not split user views into isolated "Provider" and "Recipient" experiences.
- All operators operate under unified "Dual" status (`role: 'both'`), allowing simultaneous surplus listing and demand submission.

---

## 3. UI/UX Style Guide (Industrial Neo-Brutalism)

All pages and components in `relova-dbms` must strictly adhere to the Neo-Brutalist design system:
- **Borders**: Heavy solid black borders (`border-2 border-black` or `border-[3px] border-black`).
- **Shadows**: Hard-edge geometric offset drop shadows with zero blur (`shadow-[4px_4px_0px_#000]` or `shadow-[6px_6px_0px_#000]`).
- **Color Palette**:
  - Industrial Primary Yellow: `#FDE047` / `amber-400`
  - High-Voltage Green: `#4ADE80`
  - Warning Orange: `#FB923C`
  - Critical Red: `#F87171`
  - Monochromatic Canvas: `#FFFFFF`, `#F3F4F6`, `#000000`
- **Typography**: Heavy geometric headers (`font-black uppercase tracking-tight`) paired with technical monospace labels (`font-mono text-xs`).
- **Corners**: Flat or minimal radius (`rounded-none` or `rounded-sm`).

## 4. Development & Build Rules

1. **Turbopack Notice**: On Windows environments, always execute Next.js commands with the webpack fallback (`next dev --webpack` and `next build --webpack`), already configured in `package.json`.
2. **Type Safety**: Verify TypeScript integrity before committing:
   ```bash
   npx tsc --noEmit
   npm run build
   ```
3. **Database Migrations**: Any schema adjustments must be synchronized in both `schema.sql` and `supabase/schema.sql`.
